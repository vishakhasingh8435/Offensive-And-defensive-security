# Experiment: Configure Firewall Rules Using pfSense and Enable Snort IDS

## 1. Aim
To configure basic firewall rules using pfSense and enable Snort IDS to monitor network traffic and detect suspicious activities.

## 2. Context / Theory

**pfSense Firewall:** pfSense is an open-source firewall and router platform used to control incoming and outgoing network traffic based on configured rules.

**Snort IDS:** Snort is an Intrusion Detection System (IDS) that monitors network traffic and generates alerts when suspicious or potentially malicious activity is detected.

## 3. Tools Required

- pfSense firewall
- Snort IDS package
- VirtualBox or VMware (optional)
- Kali Linux or another test client
- A web browser
- Internet or an isolated test network

## 4. Methodology / Procedure

### Step 1: Access pfSense
Open the pfSense web interface from a connected client using the firewall's LAN IP address.

### Step 2: Configure Firewall Rules
Navigate to **Firewall → Rules → LAN**.

Create appropriate rules to allow required traffic and block unauthorized traffic. Apply the changes.

### Step 3: Install Snort
Navigate to **System → Packages → Available Packages**, search for Snort, and install it if available for the installed pfSense version.

### Step 4: Configure Snort
Open **Services → Snort** and add the network interface to be monitored, such as LAN.

### Step 5: Enable Detection
Configure the available detection settings and rules, then enable Snort on the selected interface.

### Step 6: Monitor Network Traffic
Generate normal network traffic from an authorized client and check Snort's alerts and logs.

### Step 7: Analyze Alerts
Review any alerts generated by Snort and identify traffic that may require further investigation.

### Step 8: Verify Firewall Rules
Test permitted and blocked traffic using authorized test systems and confirm that the configured firewall rules behave as expected.

## 5. Results

- Basic firewall rules were configured in pfSense.
- Snort IDS was enabled on the selected network interface.
- Network traffic was monitored.
- Snort alerts and logs were examined for suspicious activity.
- Firewall behavior was checked against the configured rules.

## 6. Discussion

pfSense controls network traffic according to firewall rules, while Snort IDS inspects traffic for patterns associated with suspicious activity. Firewall rules help restrict unauthorized connections, and Snort alerts help administrators investigate possible threats. Alerts require analysis because legitimate traffic may sometimes trigger them.

## 7. Conclusion

The experiment demonstrated how to configure basic firewall rules in pfSense and use Snort IDS to monitor network traffic. It helped explain how firewalls control access and how intrusion detection systems identify potentially suspicious activity.

## 8. Improvements

- Keep Snort detection rules updated.
- Review alerts regularly to reduce false positives.
- Use appropriate firewall rules and restrict unnecessary services.
- Test configurations in an isolated lab before deployment.
- Consider an Intrusion Prevention System (IPS) configuration when active blocking is required and safely supported.

## 9. Precautions

- Perform testing only on authorized networks.
- Avoid blocking essential network services.
- Back up the pfSense configuration before making changes.
- Verify firewall rules before applying them.
- Investigate Snort alerts before treating them as confirmed attacks.
